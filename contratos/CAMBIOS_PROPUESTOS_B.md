# Cambios propuestos por el bloque B (federación y puente)

Lo implementado sigue el contrato actual. Esto aclara puntos que el contrato no fija:

1. **Proyecto de GCP en el wif-config.** El puente necesita el ID del proyecto para armar `projects/<id>/topics/telecorp-<stage>-eventos`, y no hay parámetro SSM para él. El JSON `/telecorp/<stage>/gcp/wif-config` lleva `quota_project_id = <project_id>` (campo estándar de google-auth) y el puente lo toma de ahí. Propuesta: anotarlo en integraciones.md §3. Consecuencia: las identidades federadas necesitan `roles/serviceusage.serviceUsageConsumer`, que ya otorga `gcp/terraform/federacion.tf`.
2. **Acceso directo en vez de cuenta de servicio.** Un solo wif-config compartido por el puente y la IA no puede impersonar dos cuentas de servicio, así que los roles (`pubsub.publisher`, `aiplatform.user`) se otorgan a los principalSet de cada rol IAM. El bloque G usa el wif-config tal cual, sin `service_account_impersonation_url`. Las cuentas de servicio existen como plan B.
3. **Reintentos.** "La Lambda reporta el fallo para que EventBridge reintente": en la práctica reintenta **Lambda** (invocación asíncrona, `EventInvokeConfig`, 2 reintentos → DLQ). EventBridge solo reintenta fallos de entrega. Las dos rutas terminan en `telecorp-<stage>-puente-dlq`.
4. **Entrega al menos una vez.** Un reintento vuelve a publicar en ambos destinos. Propuesta para D y E: deduplicar por `ce_id` / `id` del CloudEvent (BigQuery: `QUALIFY ROW_NUMBER() OVER (PARTITION BY JSON_VALUE(data,'$.id')) = 1` en las vistas).
5. **`subject` del CloudEvent.** Regla aplicada: `detail.zonaId` si existe; si no, `detail.incidenciaId`. Así, `Incidencia.CambioEstado` y `Notificacion.Fallida` llevan el `incidenciaId`. El atributo `zonaId` de Pub/Sub sí usa `snapshot.zonaId` para las incidencias.
6. **Event Grid.** El tema del bloque E debe tener `input_schema = "CloudEventSchemaV1_0"`, y si `local_auth_enabled = false` sigue funcionando, porque el puente usa Entra ID. El puente agrega `?api-version=2018-01-01` al endpoint si este no lo trae.
7. **Nombres de outputs de Terraform en Azure:** `federacion_tenant_id`, `federacion_client_id`, `federacion_eventgrid_endpoint` y `federacion_ssm`, con prefijo para no chocar con outputs del bloque E. Variables nuevas: `aws_account_id` (GCP y Azure), y `aws_oidc_issuer_url`, `aws_oidc_subject`, `aws_oidc_audience` (Azure). El provider `azuread` debe ser `>= 3.0`, porque se usan `client_id` y `application_id = azuread_application.*.id`.
